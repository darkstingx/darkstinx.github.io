### Escaneo de puertos

Primero, realicé un escaneo rápido de todos los puertos con nmap:

nmap -p- --min-rate 4000 -T4 -oG scan_inicial.txt 10.129.43.227

<img width="627" height="146" alt="1 Captura scaneo nmap" src="https://github.com/user-attachments/assets/f660541d-bb0e-4403-9176-c761ab5f1a4a" />

Se identifican los siguientes puertos abiertos (21, 22, 80) y se realiza un escaneo más detallado:

nmap -sVC -p 21,22,80 -oN deep.txt 10.129.43.227

<img width="671" height="259" alt="3 Escaneo profundo puertos" src="https://github.com/user-attachments/assets/a9813ff0-02af-4795-a806-7e7b2613a058" />

Vemos que hay un servidor FTP (vsftpd 3.0.3), un SSH (OpenSSH 8.2p1 Ubuntu) y un servidor web corriendo sobre Gunicorn con el título "Security Dashboard".

### Enumeración web

Al entrar en el puerto 80, encontramos un dashboard de seguridad con métricas de eventos, intentos de login fallidos y escaneos de puertos:

<img width="1916" height="939" alt="2 Página descubierta" src="https://github.com/user-attachments/assets/a7a13bb7-4413-4ba5-afb2-20d4173d17e5" />

Navegando por el panel, en la sección "Security Snapshot (5 Second PCAP + Analysis)" se genera una ruta con un ID numérico para acceder a la información de la captura:

http://10.129.43.227/data/4

<img width="640" height="38" alt="4 Posible IDOR" src="https://github.com/user-attachments/assets/771f8612-1dfd-4824-aa40-8d09d923b742" />

Esto tiene toda la pinta de un IDOR (Insecure Direct Object Reference), ya que el ID parece referenciar capturas de otros usuarios/sesiones. Para confirmarlo, hacemos fuzzing sobre el parámetro numérico con wfuzz:

wfuzz -z range,0-200 --hh 208 http://10.129.43.227/data/FUZZ

<img width="589" height="240" alt="5 IDOR Descubierto" src="https://github.com/user-attachments/assets/ee2e4171-2dd7-4e1f-8d96-db444108c5c4" />

Se confirma el IDOR: los IDs 0 y 4 devuelven código 200 con contenido, mientras que el resto de respuestas iguales (208 caracteres) se filtran como "página vacía".

### Extracción de datos

Accedemos manualmente a la ruta con ID 0, la más antigua, y encontramos una opción de descarga de la captura de tráfico en formato pcap:

http://10.129.43.227/data/0

<img width="1914" height="749" alt="6 Pagina con IDOR descubierto" src="https://github.com/user-attachments/assets/75b5e45c-6543-47c3-8814-dd426141e2fa" />

Descargamos el pcap y lo abrimos con Wireshark. Filtrando por tráfico FTP, encontramos las credenciales en texto plano, ya que FTP no cifra la autenticación:

USER nathan
PASS Buck3tH4TF0RM3!

<img width="469" height="86" alt="7 Documento de trafico de red descargado y contraseña conseguida" src="https://github.com/user-attachments/assets/21ec7135-a63f-45e6-8337-8ff8800296e7" />

Probamos las credenciales directamente por SSH:

ssh nathan@10.129.43.227

<img width="654" height="642" alt="8 Conexión ssh" src="https://github.com/user-attachments/assets/670477ad-008d-4737-a5f2-567d788d89fd" />

Acceso concedido. Ya estamos dentro como usuario nathan y podemos capturar la flag de usuario.

### Escalada de privilegios

Para la escalada, subimos y ejecutamos linpeas.sh en busca de vectores conocidos. Entre los resultados, destaca el binario pkexec con el bit SUID activo y una versión vulnerable a CVE-2021-4034 (PwnKit):

<img width="575" height="105" alt="9 Ejecución de linpeas y encontrada vulnerabilidad" src="https://github.com/user-attachments/assets/fab8c268-ee9e-4c42-a2bb-9048b49c725c" />

Descargamos el exploit público de PwnKit, lo compilamos/preparamos en la máquina víctima y lo ejecutamos:

./pwnkit.1

<img width="234" height="36" alt="10 Ejecución del payload" src="https://github.com/user-attachments/assets/3747370f-eaf1-4792-be87-886422ed7f49" />

Al ejecutarlo obtenemos una shell como root, con lo que ya podemos leer la flag de root.
